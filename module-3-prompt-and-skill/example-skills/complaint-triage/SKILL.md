# Complaint Triage

## เมื่อไหร่ใช้

- QA / Customer Service แปะข้อความร้องเรียนหลายรายการ แล้วขอให้จัดลำดับ
- ต้องการหา pattern เช่น lot เดียวกันถูกร้องเรียนซ้ำ
- **ไม่ใช้เมื่อ** ต้องการตอบลูกค้าแบบรายบุคคลเท่านั้น (ใช้ได้แต่ต้องขอให้ร่างคำตอบเพิ่ม)

## ขั้นตอน

1. อ่านเกณฑ์จาก qa_severity_criteria.md
2. แยกข้อร้องเรียนทีละรายการ ดึง: เลขที่, วันที่, ลูกค้า, ภูมิภาค, ประเภทปัญหา, SKU, lot
3. จัดระดับ สูง/กลาง/ต่ำ ตามเกณฑ์ และอธิบายเหตุผลสั้น ๆ
4. นับ SKU+lot ที่ซ้ำ ถ้าซ้ำ 2 ครั้งขึ้นไป ให้ยกระดับเป็นสูง และเสนอ hold lot
5. รายการที่ไม่มีข้อมูลสินค้า ให้ระบุ "ต้องขอข้อมูลเพิ่ม" พร้อมคำถามที่ต้องถาม
6. สรุปการดำเนินการเรียงตามความเร่งด่วน

## รูปแบบผลลัพธ์

```
# ผลคัดกรองข้อร้องเรียน <ช่วงวันที่>
สรุป: N รายการ | สูง a | กลาง b | ต่ำ c

| # | ลูกค้า | ประเภท | SKU | lot | ระดับ | เหตุผล | การดำเนินการ |

## Lot ที่ต้องเฝ้าระวัง / hold
## รายการที่ต้องขอข้อมูลเพิ่ม (พร้อมคำถาม)
## ลำดับการติดต่อกลับวันนี้
```

## ตัวอย่าง

**ข้อมูลเข้า:** complaints.txt (12 รายการ)

**ผลลัพธ์:** ระบุว่า FZ-1042 lot L2609A ถูกร้องเรียน 3 ครั้ง (กลิ่น, สิ่งแปลกปลอม, ผู้ป่วย) ระดับสูง เสนอ hold lot และตรวจสต็อกในคลังบางนา/วังน้อย

## ข้อควรระวัง

- คำว่า "ท้องเสีย" หรือ "ผู้ป่วย" = สูงเสมอ
- ห้ามสรุปสาเหตุว่าเป็นความผิดของบริษัทจนกว่าจะตรวจสอบ ใช้คำว่า "ต้องตรวจสอบ"
