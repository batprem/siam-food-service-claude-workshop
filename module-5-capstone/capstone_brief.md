# Capstone: ทีม Agent ต่อสายงาน Marketing → Buyer → Production → Sales

บริษัท สยาม ฟู้ด เซอร์วิส (ข้อมูลจำลอง) จะออกแคมเปญ **"เมนูปลายปี 2569"** สำหรับลูกค้าโรงแรมและร้านอาหาร ช่วง พ.ย.–ธ.ค. 2569
แต่ละกลุ่มรับบทเป็น 1 แผนก และสร้าง Agent (Claude + Skill + ไฟล์ข้อมูล) ที่รับแผนจากแผนกก่อนหน้า แล้วส่งแผนของตัวเองให้แผนกถัดไป

## Pipeline

```
[กลุ่ม 1 Marketing] --marketing_plan.md--> [กลุ่ม 2 Buyer] --purchase_plan.md--> [กลุ่ม 3 Production] --production_plan.md--> [กลุ่ม 4 Sales] --sales_plan.md--> นำเสนอ
```

รูปแบบไฟล์ส่งต่อ (handoff) = **Markdown** ตาม template ใน `handoff_templates/` เท่านั้น เพื่อให้กลุ่มถัดไปให้ Claude อ่านต่อได้ทันที

## ข้อมูลที่ใช้ได้

- `module-3-prompt-and-skill/sales_mock.csv` (ยอดขาย 12 เดือน)
- `module-3-prompt-and-skill/inventory_mock.xlsx` (สต็อกและวันหมดอายุ)
- `module-3-prompt-and-skill/complaints.txt` (ข้อร้องเรียน — ระวัง lot ที่มีปัญหา)
- ข้อมูลจาก Fabric connector (ถ้ายังเชื่อมอยู่)

## สิ่งที่ Agent ของแต่ละกลุ่มต้องส่งออก

### กลุ่ม 1 — Marketing (เริ่มต้น ไม่มี input จากกลุ่มอื่น)
- เลือก 3 หมวดสินค้า / 5 SKU เด่นสำหรับแคมเปญ พร้อมเหตุผลจากข้อมูลยอดขาย
- กลุ่มเป้าหมาย (ภูมิภาค + ประเภทลูกค้า) และเป้ายอดขายแคมเปญ (บาท)
- ประมาณการปริมาณขาย (หน่วย) ต่อ SKU ต่อเดือน
- ไฟล์: `marketing_plan.md`

### กลุ่ม 2 — Buyer
- รับ `marketing_plan.md` → เทียบกับสต็อกใน inventory_mock.xlsx
- คำนวณต้องสั่งซื้อเพิ่มเท่าไหร่ต่อ SKU (คำนึงถึงสต็อกที่ใกล้หมดอายุ / lot ที่ถูก hold)
- งบประมาณจัดซื้อ, lead time, ความเสี่ยงซัพพลายเออร์
- ไฟล์: `purchase_plan.md`

### กลุ่ม 3 — Production / Operation
- รับ `purchase_plan.md` → วางแผนรับสินค้า จัดเก็บ (คลังไหน) และตารางจัดส่ง
- ระบุกำลังคลังเย็นที่ต้องใช้ ความเสี่ยง cold chain และแผนสำรอง
- ไฟล์: `production_plan.md`

### กลุ่ม 4 — Sales
- รับ `production_plan.md` → แผนเข้าพบลูกค้า 10 รายแรก, สคริปต์เสนอขาย, โปรโมชัน, เป้ารายภูมิภาค
- ร่างข้อความ LINE/อีเมลเสนอลูกค้า 1 ฉบับ
- ไฟล์: `sales_plan.md`

## กติกาการทำงาน

1. ทุกกลุ่มต้องเขียน **SKILL.md** ของแผนกตัวเองอย่างน้อย 1 ไฟล์ (ใช้ `SKILL_TEMPLATE.md`)
2. ผลลัพธ์ทุกตัวเลขต้องอ้างอิงได้ว่ามาจากไฟล์ไหน
3. ถ้า input จากกลุ่มก่อนหน้าไม่ครบ ให้ Agent ตั้งสมมติฐานและระบุชัดเจนว่า "สมมติว่า..."
4. ส่งไฟล์ handoff ให้กลุ่มถัดไปผ่านโฟลเดอร์แชร์ที่ผู้สอนกำหนด

## Timebox (รวม 120 นาที)

| เวลา | กิจกรรม |
|---|---|
| 0–10 นาที | อ่าน brief, แบ่งบทบาทในกลุ่ม (คนสั่ง Claude / คนตรวจ / คนจดปัญหา) |
| 10–35 นาที | เขียน SKILL.md + เตรียมข้อมูล + รันรอบแรก |
| 35–45 นาที | Marketing ส่ง marketing_plan.md |
| 45–60 นาที | Buyer ส่ง purchase_plan.md |
| 60–75 นาที | Production ส่ง production_plan.md |
| 75–90 นาที | Sales ส่ง sales_plan.md |
| 90–120 นาที | แต่ละกลุ่มนำเสนอ 5 นาที + ถาม-ตอบ + ตัดสิน |

ระหว่างรอ input กลุ่มที่ยังไม่ถึงคิวให้เตรียม Skill และทดสอบด้วยข้อมูลสมมติไปก่อน

## เกณฑ์ตัดสิน (100 คะแนน)

| เกณฑ์ | คะแนน | สิ่งที่ดู |
|---|---|---|
| ความถูกต้องของข้อมูล | 25 | ตัวเลขตรงกับไฟล์ต้นทาง ไม่แต่งตัวเลข |
| คุณภาพ Skill | 25 | มีเมื่อไหร่ใช้/ขั้นตอน/รูปแบบผลลัพธ์ชัด รันซ้ำแล้วได้ผลคงที่ |
| การส่งต่อ (handoff) | 20 | กลุ่มถัดไปใช้ไฟล์ได้ทันทีโดยไม่ต้องถามกลับ |
| การจัดการความเสี่ยง | 15 | เห็นประเด็น lot มีปัญหา สินค้าใกล้หมดอายุ cold chain |
| การนำเสนอ | 15 | สั้น ชัด บอกได้ว่า Claude ช่วยตรงไหนและคนตัดสินใจตรงไหน |

## คำถามที่กรรมการจะถาม

- ถ้าข้อมูลจากกลุ่มก่อนหน้าผิด Agent ของคุณจับได้ไหม
- ตัวเลขไหนที่ Claude เดา และคุณตรวจอย่างไร
- ถ้าต้องทำทุกเดือน จะต้องแก้ Skill ตรงไหน
